# 底値を掴め！ DAILY BOTTOM

`daily_bottom_spec_v0.3.md` の **Phase 1（MVP）** の実装。

- `src/core/` … 生成と判定。DOM 非依存の純粋関数。ブラウザ・Nodeシミュレーション・Phase 2 のサーバー検証で同じコードを使う
- `src/game/` `src/render/` `src/modes/` … 状態遷移・Canvas 描画・DAILY / PRACTICE
- `sim/` … Bot シミュレーション（§10）。Node から `src/core` を直接呼ぶ
- `tests/` … 決定性・判定・表示のテスト

演出は仕様どおりテキストと図形のプレースホルダー。キャラクターのカットイン・BGM・サーバーランキングは Phase 2。


## 仕様から動かした点

### 1. シナリオ抽選をリトライの外に出した

§5.1 は「不合格なら同じRNGを進めて再生成」とだけ書いてあるが、再生成のたびにシナリオを引き直すと、
受理条件のゆるいシナリオが実際の出現率で有利になる（実測で V が 46%、SAUCER が 9% になった）。
シナリオは最初に一度だけ引き、リトライは同じシナリオの中で行う。

### 2. 事前表示 12本 → 18本、表示ウィンドウ 30本 → 18本

事前表示が12本だと LIVE が18本進むまでウィンドウが埋まらず、その空き幅が経過時間になる。
ウィンドウを18本にし、事前表示も18本にして、**最初のフレームから最後まで常に18本ちょうど**を描く。

`tests/display.test.ts` が全ティックについて「描画される足が常に18本」「1本進むごとにちょうど1本だけ
左へスクロール」「形成中の足は常に右端」を機械的に検査している。

| 経路 | 状態 |
|---|---|
| チャート右側の空白 | 常に18本で埋まるので発生しない |
| プログレス表示 | 無し |
| 残り時間 | 無し。ヘッダは相場名と DAILY の何相場目かだけ |
| ローソク足の総数 | 画面には常に18本。総数は出ない |
| スクロール挙動 | 1本／0.8秒で一定。序盤と終盤で変わらない |
| 終盤固有の視覚変化 | 無し。BOTTOM マーカーは PLAYBACK 以降でのみ描く |

### 3. 真の SMALL_BOUNCE / DECEL の経路を追加

**SMALL_BOUNCE** はダマシ専用で信頼度が構造的に 0% だった。SAUCER・CLIMAX・RANGE の底まわりに、
**底の1本あと**に出る真の小反発を確率 0.21 で追加した。ダマシ（3,460）が真（962）を大きく上回るので、
小反発だけでは底が確定しない。

**DECEL** は真の兆候が構造上つねに底から4本以上離れていた（実測 1.7%）。記録位置を底固め／レンジ側の
**底の±1本以内**に移し、CLIMAX・RANGE にも追加した。値は変えていない（セグメント定義の
ドリフト・ボラ・出来高の低下が減速そのものなので `markOnly`）。「減速→反転」（SAUCER・CLIMAX・RANGE）と
「減速→再下落」（§5.7 の一時減速ダマシ）が真 3,755 / ダマシ 4,562 とほぼ半々で共存する。

### 4. 底値圏の滞在時間を短縮（今回の主な変更）

RandomBot の SUPER以上の率は「SUPER圏のティック数 ÷ 240」と厳密に一致する。
つまりランダムが当たるのは、価格が底値圏に長く留まるからで、そこを削った。
**各シナリオの形状は残したまま**、底値圏を抜ける速さだけを上げている。

| シナリオ | 変更 | ねらい |
|---|---|---|
| SAUCER | 底固めを 5〜8本・平坦 → 3〜4本・ドリフト −1.3→+2.2 の「丸い底」に。減速の終端を −0.1 → −0.9 | 平坦だと区間まるごとが SUPER 圏に入る。丸い底にすると皿型はむしろ強まり、抜けは速くなる |
| CLIMAX | 底固めを 4〜7本・平坦 → 3〜5本・ドリフト 0→+1.2。上放れ 0.8 → 1.6 | セリクラ直後の落ち着きは残しつつ、安値に張り付かせない |
| RANGE | 下値レンジのドリフト −0.2 → −0.7。急反転 2.5 → 3.0 | 低ボラのまま緩やかに切り下がる形にして、底値圏にいる時間を後半に寄せる |
| DOUBLE | 反発 1.2 → 1.9、二番底 3〜4本 → 3本・−2.4。二つの安値の差の受理窓を 0.05〜1.0V → 0.8〜2.5V | 差が 1ATR 未満だと二つの安値が両方 SUPER 圏に入る |
| V / FAKE | 反発を 2.2 → 2.6 / 1.5 → 1.9 | 他シナリオと歩調を合わせる |

結果、SUPER圏のティック数は平均 25.1 → 20.0、シナリオ間のばらつきも
15.5〜33.8 → 15.5〜23.1 に縮まった。RandomBot の SUPER以上は 10.4% → 7.9%。

形が V字化していないことは確認済み（底値0.5ATR以内の足数：V 2.1本 / SAUCER 2.9本 / RANGE 2.9本、
底±5本の実体は V 2.04V に対し SAUCER 1.39V・RANGE 1.36V）。

### 5. 兆候信頼度の設定値（§10.2 #6 の更新）

旧設計値（下ヒゲ70% / 大陽線65% / 出来高65% / 減速45% / 小反発20%）は**廃止**。
シミュレーションで、信頼度を上げるほど複合戦略とランダム・時刻戦略の差が単調に広がり、
かつ単純戦略が支配的にならないことが確認できたため、次の値を Phase 1 の設計値とした。

| 兆候 | 新設計値 | 旧設計値 |
|---|---|---|
| 下ヒゲ（WICK） | 82% | 70% |
| 大陽線（BIG_GREEN） | 74% | 65% |
| 出来高急増（VOLUME） | 70% | 55% |
| 減速（DECEL） | 60% | 45% |
| 小反発（SMALL_BOUNCE） | 30% | 20% |

真の兆候は底の±2本以内にほぼ100%出るので、実測信頼度はおおむね
「真の兆候 ÷（真の兆候＋ダマシ）」になる。設計値に合わせてダマシ側だけを較正した。

- 個数 k の分布：`[29, 45, 21, 5]` → `[58, 27, 12, 3]`
- 種別の重み（下ヒゲ / 出来高 / 減速 / 小反発）：`[5, 20, 48, 36]` → `[4, 14, 44, 38]`
- FAKE シナリオの構造的ダマシ：第一安値の下ヒゲ 0.5 → 0.13、出来高 0.5 → 0.17、
  ダマシ反発の大陽線 0.72 → 0.47

### 6. §10.2 の合格基準そのものを更新

旧基準の「RandomBot の SUPER以上 ≤5%」は**絶対条件から外した**。
底値圏の滞在時間を削る作業で、ランダムの当たりやすさには構造的な下限があることが分かったため
（価格は必ず底の前後で1ATR以内を通過する）。

代わりに最重要の条件を次に置いた。

> 市場情報を複合的に利用する戦略が、ランダム・時刻のみ・下落率のみ・単一兆候／2兆候のどれよりも
> SUPER以上・ULTRA以上の両方で上回っていること

SUPER / ULTRA をスキル評価の中心とし、**GOD には完全なスキル分離を求めない**。
GOD 圏は 240ティック中 2.6〜5.3ティックしかなく、約0.3秒の精度を要求する一方、
兆候はすべて足単位（0.8秒）の情報なので、腕では詰められない領域が残る
（底値ティックを知っている OracleBot ですら反応遅延だけで 22.6% に落ちる）。
GOD は「十分な判断で到達確率は上げられるが、最後は精密なタイミングも要る特別なレア枠」として扱う。

先読み条件（`buyTick <= bottomTick`）は検討のうえ**不採用**。許容幅を 0〜∞ のどこに置いても
Combo/Random は 3.8〜4.2倍、Combo/Time は 0.88〜1.09倍で横ばいのまま改善せず、
許容 0 では OracleBot が 0.00% になる。詳細は `sim/out/analysis.md`。

### 7. Bot 側の実装

- **ティック単位**：§10.1 は「そのティックまでに描画された内容」を使ってよいとしており、
  §4 のとおり人間は足の途中で BUY できる
- **複数足の特徴量**：`dry`（出来高枯れ）と `flat`（値幅の収縮）。
  これが無いとスパイクの出ない SAUCER・RANGE で複合Botがランダムより弱かった
- **ExpertBot ≥ ComboBot の構造的保証**：ComboBot の重みをそのまま
  `freshLow=6`（安値からの距離を問わない）`patience=99`（反転確認を使わない）で使う設定を
  ベースライン候補に置き、採用条件を「平均スコアと SUPER以上の率のどちらもベースライン以上」とした。
  同じパラメータなら Bot の乱数列も同じなので、最悪でも ComboBot と完全に一致する

### 支配戦略のチェック

単純戦略（単一兆候5種・2兆候5種）の最良は平均スコア 258（BigGreenBot）で、
Combo 370 / Expert 380 を大きく下回る。SUPER以上の最良も 14.9%（Pair 下ヒゲ+出来高）で、
Combo 30.1% / Expert 31.6% の半分以下。この Pair は NO TRADE が 54.9% あり、
当たれば精度は高いが機会を半分捨てるため、平均では 158 にとどまる。
「ひとつ、あるいは二つの兆候だけ覚える」が支配戦略にはなっていない。

## Phase 1 の凍結

上記の最終シミュレーションで重大な回帰も支配戦略も確認されなかったため、
**チャート生成・判定・兆候信頼度・Bot検証を Phase 1 完了として凍結する。**

凍結対象：

- `src/core/`（生成・判定の全パラメータ、ランク閾値 GOD 0.2 / ULTRA 0.5 / SUPER 1.0 / GREAT 2.0 / GOOD 4.0）
- 兆候の設計信頼度（82 / 74 / 70 / 60 / 30%）
- `sim/`（Bot 群と合格基準）
- `tests/determinism.snapshot.json`（固定シード10本のハッシュ）

生成器を変更した場合は `npm run snap` でスナップショットを作り直す必要があり、
その時点で凍結は解除されたものとして再検証すること。

## 残っている課題（Phase 2 以降）

- **GOD 帯は腕だけでは分離しない**。時刻のみの戦略（3.1%）と複合戦略（5.8%）が近い。
  構造的な理由は上記のとおりで、レア演出枠として扱う前提
- **§5.2 の実機決定性の突き合わせが未実施**。`tests/determinism.snapshot.json` に
  固定シード10本のハッシュがあるので、iOS Safari・Android Chrome で同じ比較を走らせれば確認できる
- **§13 のとおり、0.8秒/足で人間が兆候を読めるかは未検証**。5〜10人のプレイテストが必要。
  Bot の成績は人間の熟練者の代理にすぎない
- シェア URL は `src/ui/share.ts` の `SHARE_URL` にプレースホルダーを置いてある
- 演出はプレースホルダーのまま（Phase 2）
